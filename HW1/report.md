**Условие задачи:**
Разработать консольное приложение, моделирующее работу читателей и писателей с базой данных. База данных представляет собой отсортированный одномерный массив положительных целых чисел. 
С ним одновременно работают читатели и писатели:
- **Читатель** случайно выбирает значение по индексу, вычисляет для него число Фибоначчи и выводит результат.
- **Писатель** случайно выбирает запись, заменяет ее новым положительным числом и восстанавливает отсортированный порядок массива. 

**Ключевое правило:** На протяжении каждой операции изменения писатель имеет самый главный доступ ко всей базе (с ней не работают ни другие писатели, ни читатели в этот момент). При отсутствии действий писателей читатели могут выполнять операции параллельно(на деле иногда будет казаться что они делают это подряд, но это илюзия, возникающая когда действия обрабатываются быстрее чем успевает дойти очередь до следующего запроса). Политика доступа должна задаваться явно(приоритет читателям или писателям).

## 2. Архитектура и взаимодействие процессов
* **База данных (Общий ресурс):** Представлена структурой данных `database_t`, которая содержит динамический массив, его размер, счетчики потоков и примитивы синхронизации POSIX: глобальный мьютекс (`pthread_mutex_t`) и условные переменные (`pthread_cond_t`).
* **Участники:** Каждый читатель и писатель работает в отдельном POSIX-потоке (`pthread_t`), которые порождаются в главном потоке программы.
* **Механизм взаимодействия:** Перед началом работы с массивом поток делает запрос на доступ (`db_read_lock` или `db_write_lock`). Если доступ запрещен выбранной политикой (например, очередь отдана писателям), поток "засыпает" с помощью `pthread_cond_wait`. После окончания работы поток снимает блокировку и "будит" остальные потоки через `pthread_cond_signal` или `pthread_cond_broadcast`.

## 3. Пользовательский интерфейс
Программа представляет собой консольное приложение без интерактивного ввода во время работы. Вся конфигурация задается при запуске с помощью аргументов командной строки (разбираются стандартной библиотечной функцией `getopt_long`).

Вывод спроектирован так, чтобы максимально наглядно отражать суть: программа логирует каждый запрос доступа, вход в БД, результаты операций (чтение/запись/Фибоначчи) и выход из БД. Чтобы логи из разных потоков не смешивались на экране в "кашу", реализована специальная функция `safe_printf` с собственным мьютексом, гарантирующая целостность выводимых строк.

## 4. Запуск и завершение работы
Приложение поддерживает гибкую настройку через флаги:
* `-r, --readers` — Количество читателей
* `-w, --writers` — Количество писателей
* `-s, --size` — Размер массива
* `-m, --max-val` — Максимальное случайное число
* `-o, --ops` — Количество операций на поток
* `-p, --policy` — Политика (`readers`, `writers` или `fair`)
* `--sleep-min` / `--sleep-max` — Диапазон задержек (мс) для эмуляции работы

**Пример запуска:**
```bash
./HW_1 -p fair -r 5 -w 2 -o 3
```

**Завершение:** 
Программа завершается корректно и автоматически после того, как все потоки отработают заданное число итераций (ключ `-o`). Главный процесс дожидается дочерних потоков с помощью `pthread_join`, освобождает всю память (массивы, структуры потоков) и удаляет мьютексы. Утечек памяти и вечных зависаний (deadlocks) не происходит.
