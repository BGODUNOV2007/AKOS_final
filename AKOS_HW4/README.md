# Читатели и писатели по TCP

ИДЗ № 4 по АКОС, вариант 2. Годунов Борис Эдуардович, группа 252. Полный отчёт с результатами и разбором критериев находится в [report.pdf](report.pdf).

## Быстрый запуск

В Linux из корня проекта выполните

```sh
make demo
```

Команда собирает приложения, запускает сервер на `127.0.0.1:5000`, наблюдателя, двух читателей и писателя. На экране появляются события в реальном времени. После шести чтений и двух записей все процессы завершаются. Скрипт печатает каталог с журналами и проверяет полученную историю. Другой порт можно выбрать командой `PORT=5010 make demo`.

Сборке нужны C11-компилятор, libc и GNU Make. Демонстрация использует Bash и Python 3. Для ручного запуска пяти C-программ Python не требуется.

## Запуск по уровням критериев

В следующих командах каждое длительно работающее приложение запускают в своём терминале. При распределённом запуске соберите проект на каждом Linux-компьютере. На сервере укажите адрес его сетевого интерфейса или `0.0.0.0`, а у клиентов замените `127.0.0.1` на доступный IPv4-адрес машины сервера. Все используют один и тот же порт. Конфигурацию читает только сервер.

**4–5 баллов.** Запустите сервер, двух читателей и одного писателя. Участник выводит собственные запросы, выданные ему разрешения и результаты. Сервер выводит параметры запуска и итог. Последний аргумент сервера — необязательный путь для записи полного журнала. Например, для нового файла используйте `/tmp/akos4-events.log`. При старте файл по указанному пути открывается заново.

```sh
make
bin/server 127.0.0.1 5000 configs/demo.conf
bin/reader 127.0.0.1 5000 1
bin/reader 127.0.0.1 5000 2
bin/writer 127.0.0.1 5000 1
```

**6–7 и 8 баллов.** После старта сервера в одном или нескольких терминалах выполните `bin/monitor 127.0.0.1 5000`. Чтобы увидеть весь короткий сеанс, подключайте наблюдателей раньше работников. Поздний наблюдатель сразу получает массив, активные и ожидающие сеансы, выполненные квоты и номер последнего события. Дальше он видит единый поток новых событий. При закрытии окна наблюдатель отключается. Повторный запуск создаёт новый сеанс.

**Выше 8 баллов.** Для демонстрации с ручным управлением запустите сервер с `configs/live.conf` и те же клиентские команды. Квота 0 включает неограниченный режим. Управление выполняют из ещё одного терминала.

```sh
bin/control 127.0.0.1 5000 list
bin/control 127.0.0.1 5000 drop W 1
bin/writer 127.0.0.1 5000 1
```

Команда `drop W 1` отключает писателя. Запустите его снова с тем же ID в отдельном терминале. Аналогично работают `drop R 1` и `drop M 1`. Номер наблюдателя показывает `list`. Состояние БД и счётчики сохраняются в работающем сервере. Один ID каждой рабочей роли может иметь один открытый сеанс.

Для общей остановки выполните `bin/control 127.0.0.1 5000 stop` или нажмите Ctrl+C в терминале сервера. Участники получают сообщение об остановке даже во время модельной задержки. В конечном режиме сервер автоматически завершается, когда каждый заданный участник исчерпал квоту. Если участника отключили раньше, возобновите его с тем же ID или остановите модель командой управления.

## Конфигурация

Формат `ключ=значение`. Пробелы вокруг значений и комментарии после `#` допускаются. Все ключи представлены в `configs/demo.conf`. Значения в диапазонах включают обе границы.

| Ключ | Значение |
| --- | --- |
| `db` | Начальные положительные числа через запятую. Их количество задаёт размер от 1 до 128. Сервер сортирует массив при старте. |
| `readers`, `writers` | От 0 до 32 участников каждой роли, суммарно минимум один. Номера участников каждой роли начинаются с 1. |
| `reader_ops`, `writer_ops` | Одно число на всех участников роли или список по ID. От 1 до 1 000 000 операций, 0 для бесконечного режима. |
| `index` | Интервал индексов в формате `0-4`; последний индекс меньше размера массива. |
| `value` | Интервал новых значений. Для `db` и `value` поддерживаются числа 1–93, чтобы F(n) точно помещалось в uint64_t. |
| `gap_ms`, `read_ms`, `write_ms` | Интервалы ожидания до запроса, длительности чтения и записи, от 0 до 60 000 мс. |
| `policy` | `fair` — FIFO с группированием последовательных читателей; `readers` или `writers` — приоритет соответствующей роли, FIFO внутри роли. |
| `seed` | Целое число 0–2 147 483 647. Выбор индекса, значения и задержек воспроизводится для заданных роли, ID и номера операции. Порядок сетевых событий зависит от исполнения. |

## Проверка и сохранённые результаты

```sh
make test
python3 tests/audit.py results/demo.log
```

Интеграционные тесты поднимают временные серверы на свободных портах loopback, запускают C-программы и используют управляемых протокольных клиентов, когда нужен точный порядок конкурирующих запросов. Аудитор читает начальную БД из журнала, восстанавливает каждую запись, пересчитывает F(n) и независимо проверяет владельцев базы между событиями. При расхождении проверка завершается ненулевым кодом. Для своего прогона передайте путь к журналу четвёртым аргументом сервера, затем передайте этот файл аудитору.

| Каталог | Содержимое |
| --- | --- |
| `src/` | Сетевые приложения, конфигурация, функции TCP и Фибоначчи |
| `configs/`, `scripts/` | Конечный и неограниченный режимы, сценарий демонстрации |
| `tests/` | 13 интеграционных сценариев и независимый аудитор журнала |
| `results/` | Реальные журналы, локальные представления клиентов и протокол прогона |
| `PROMPTS.md` | Пользовательский запрос, использованный при генерации решения |
