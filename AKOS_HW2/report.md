# Отчет по заданию 2 «Читатели и писатели»

## 1. Общая информация
* **Исполнитель:** Годунов Борис Эдуардович
* **Группа:** 252
* **Вариант:** 2

**Условие задачи:**
«База данных» представлена отсортированным одномерным массивом положительных целых чисел. Одновременно с ней работают читатели и писатели. Читатель случайно выбирает значение по индексу, вычисляет число Фибоначчи и выводит результат. Писатель случайно выбирает запись, заменяет её новым числом и восстанавливает сортировку. На время записи писатель владеет исключительным доступом — ни другой писатель, ни читатель с ним не работает. При отсутствии писателей любое количество читателей может работать параллельно. Политика доступа задаётся явно.

## 2. Сценарий: сущности → потоки

| Сущность предметной области | Программный объект |
|---|---|
| База данных | Структура `database_t`: массив `data[]`, примитивы синхронизации |
| Читатель | POSIX-поток `pthread_t`, функция `reader_thread()` |
| Писатель | POSIX-поток `pthread_t`, функция `writer_thread()` |
| Исключительный доступ писателя | Блокировка `db_write_lock()` / `db_write_unlock()` |
| Параллельное чтение | Счётчик `active_readers`, несколько потоков в секции чтения |
| Политика доступа | Набор реализаций `{readers_pref, writers_pref, fair}` |

**Взаимодействие:** Перед входом в базу данных каждый поток вызывает `db_read_lock()` или `db_write_lock()`. Внутри функции поток проверяет счётчики состояния (защищённые `pthread_mutex_t`) и, если доступ запрещён политикой, блокируется. После работы поток вызывает `unlock()` и пробуждает ожидающих участников.

**Два варианта синхронизации реализованы в отдельных директориях:**

* `sem/`      — семафоры POSIX (`sem_t`): блокировка через `sem_wait`, пробуждение через `sem_post`
* `condvar/`  — условные переменные (`pthread_cond_t`): блокировка через `pthread_cond_wait`, пробуждение через `pthread_cond_broadcast`

## 4. Описание пользовательского интерфейса

Обе программы — неинтерактивные консольные приложения. Параметры задаются аргументами при запуске (парсинг через `getopt_long`):

| Флаг | Описание | По умолчанию |
|---|---|---|
| `-r N` | Количество читателей | 3 |
| `-w N` | Количество писателей | 2 |
| `-s N` | Размер массива | 10 |
| `-m N` | Максимальное значение элемента | 100 |
| `-o N` | Операций на поток (0 = бесконечно) | 5 |
| `-p POLICY` | Политика: `readers`, `writers`, `fair` | `fair` |
| `--sleep-min MS` | Мин. задержка между операциями (мс) | 100 |
| `--sleep-max MS` | Макс. задержка между операциями (мс) | 500 |
| `-l FILE` | Путь к лог-файлу | (не сохраняется) |

Для атомарности вывода реализована функция `safe_printf()`, захватывающая отдельный мьютекс `g_print_mutex`. Весь вывод одновременно дублируется в лог-файл, если он указан флагом `-l`.

## 5. Варианты запуска и завершения

```bash
# Сборка
make

# Версия на семафорах, политика fair, 3 читателя, 2 писателя
sem/rw_sem -p fair -r 3 -w 2 -o 5

# Версия на условных переменных, приоритет писателям
condvar/rw_cv -p writers -r 2 -w 4 -o 4

# Бесконечный режим (завершение по Ctrl+C)
sem/rw_sem -p fair -r 3 -w 2 -o 0

# С сохранением лога в файл
sem/rw_sem -p fair -r 3 -w 2 -o 5 -l run.log

# Запуск всех автотестов
make test
```

**Завершение:**

* **Штатное:** главный поток ждёт все дочерние через `pthread_join`. Как только все выполнят `num_ops` операций — программа завершается.
* **По сигналу SIGINT (Ctrl+C):** обработчик `sigint_handler` устанавливает атомарный флаг `stop_flag=1`. Все потоки проверяют его перед каждой итерацией и немедленно выходят. В семафорной версии дополнительно вызываются `sem_post` для пробуждения заблокированных потоков.

## 7. Сравнение реализаций

| Критерий | `sem/` (семафоры) | `condvar/` (условные переменные) |
|---|---|---|
| Примитив ожидания | `sem_wait(sem_t*)` | `pthread_cond_wait(cond, mutex)` |
| Пробуждение | `sem_post()` (точечное) | `broadcast()` / `signal()` |
| Состояние в примитиве | Счётчик внутри семафора | Внешние счётчики + условие в `while` |
| Ложные пробуждения | Невозможны (счётчик) | Защита через `while`-цикл |
| Точность пробуждения | Точная (один `post` = один поток) | `broadcast` будит всех, лишние засыпают обратно |
| Стандарт | POSIX | POSIX (pthread) |

## 8. Использование ИИ
Ниже приведены ключевые этапы, где ИИ был задействован:

* Обнаружение и исправление бага с неатомарным выводом строки писателя (два отдельных `safe_printf` → один вызов с буфером)
* Написание автоматических тестовых скриптов

**Правки кода:** в процессе разработки ИИ самостоятельно обнаружил и исправил следующие проблемы:
1. Дублирование строки вывода "Операций на поток" в `main.c`
2. Неатомарность вывода массива писателем (исправлено формированием строки в буфере)
3. Некорректный вызов `pthread_mutex_lock` внутри signal handler (исправлено на async-safe подход)
